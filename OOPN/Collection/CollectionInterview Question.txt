🔐 Masked / Tricky Questions (These test depth)
1.How does HashMap handle collisions internally?

Answer: Uses chaining (LinkedList or Tree structure from Java 8 onward).

2.What will happen if two keys have the same hashCode?

They will be placed in the same bucket; equals() will be used to differentiate them.

3.Can we insert a duplicate key in a HashMap?

No — it will overwrite the previous value.

4.Why is HashSet backed by HashMap?

It uses keys of the map to store set elements (value is a dummy object).

5.What is the time complexity of get() and put() in HashMap?

Best case: O(1); Worst case: O(n) (but rare due to resizing and tree optimization).

6.What happens when the number of elements exceeds the capacity in HashMap?

It resizes (doubles the capacity) and rehashes all keys.

7.What is the difference between Comparable and Comparator?

Comparable is used for natural ordering, Comparator for custom ordering.

8.Can we make a custom object a key in HashMap? What should we override?

Yes — override equals() and hashCode() properly.

9.What is the difference between ConcurrentHashMap and Collections.synchronizedMap()?

ConcurrentHashMap is more efficient and divides locking internally by segments.

10.How does TreeMap store elements?

It uses a Red-Black tree (a type of self-balancing binary search tree).

Q8.What is the difference between fail-fast and fail-safe iterators?

A= Fail-fast: iterators throw a ConcurrentModificationException if the collection is changed while  
   iterating.
   Example: ArrayList, HashMap iterators.


Fail-Safe: iterators are available in concurrent collections like CopyOnWriteArrayList or ConcurrentHashMap.  
    These collections allow modifications during iteration without throwing exceptions.


Fail-safe iterators do not throw exceptions because they work on a copy of the collection.
Example: ConcurrentHashMap, CopyOnWriteArrayList.

What is ConcurrentHashMap?

ConcurrentHashMap is a thread-safe version of HashMap in Java.

It allows multiple threads to read and write safely without throwing ConcurrentModificationException.

It is part of the java.util.concurrent package (since Java 1.5).



Q9.How does HashSet work internally?

A=Hashset is a child class of set interface, and it is based on the hashmap. hashset does not allow 
  duplicate element. Insertion order is not preserved. Internally ,when we add an element to a HashSet, it is stored as a key in the underlying HashMap, and the value is a constant dummy object (usually Boolean.TRUE). This is because HashMap stores data in key-value pairs, and HashSet only needs the keys. HashSet relies on the hashCode() and equals() methods to ensure uniqueness."
